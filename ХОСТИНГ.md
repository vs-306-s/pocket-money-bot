# 🚀 Как выложить бота на сервер

Бот работает на длинном опросе (long polling): вебхук, белый IP и домен не нужны —
достаточно одного постоянно запущенного процесса с интернетом.

## Что подготовить

1. Токен бота от @BotFather.
2. `config.json` со своим `bot_token` (и, при необходимости, `proxy`).
3. Сервер: любая VPS с Ubuntu 22.04+ (1 ГБ памяти хватит), либо PaaS с поддержкой Docker.

Файлы-секреты (`config.json`, `data/`) на GitHub лучше не заливать — они в `.gitignore`.
На сервере `config.json` создай вручную из `config.example.json`.

---

## Вариант 1: VPS + Docker (рекомендую)

```bash
# на сервере
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
git clone https://github.com/<твой-аккаунт>/pocket-money-bot.git
cd pocket-money-bot

cp config.example.json config.json
nano config.json          # впиши bot_token

docker build -t pocket-money-bot .
docker run -d --name pocket-money \
  --restart unless-stopped \
  -v "$PWD/data:/app/data" \
  pocket-money-bot
```

Флаг `--restart unless-stopped` поднимает бота после перезагрузки и падений.
Логи: `docker logs -f pocket-money`.

## Вариант 2: VPS + systemd (без Docker)

```bash
sudo apt update && sudo apt install -y python3 python3-venv
git clone https://github.com/<твой-аккаунт>/pocket-money-bot.git /opt/pocket-money-bot
cd /opt/pocket-money-bot

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config.example.json config.json
nano config.json
```

Создай юнит `/etc/systemd/system/pocket-money-bot.service`:

```ini
[Unit]
Description=Pocket Money Bot
After=network-online.target

[Service]
WorkingDirectory=/opt/pocket-money-bot
ExecStart=/opt/pocket-money-bot/.venv/bin/python main.py
Restart=always
RestartSec=10
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pocket-money-bot
sudo systemctl status pocket-money-bot
journalctl -u pocket-money-bot -f
```

## Вариант 3: Pазличные PaaS (Railway, Render, Fly.io)

В проекте уже есть `Dockerfile` и `Procfile` — они подходят «как есть».

1. Залей проект в GitHub (см. `README.md`).
2. На платформе выбери «Deploy from Dockerfile» или «Worker» (не web-сервис —
   боту не нужен порт).
3. Переменные окружения:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `DATA_DIR` | `/data` (если платформа даёт постоянный диск) |
| `PROXY` | `http://user:pass@host:port`, если Telegram недоступен напрямую |
| `TZ_OFFSET` | `3` для Москвы |

4. Обязательно подключи постоянный диск (volume) к каталогу данных — иначе после
   перезапуска база с оценками и настройками пропадёт.

## Полезно знать

* **Зависимости.** Для отчётов нужен `openpyxl` — он есть в `requirements.txt`,
  в `Dockerfile` ставится автоматически.
* **Прокси.** Если сервер в стране, где Telegram заблокирован, добавь в `config.json`
  `"proxy": "http://127.0.0.1:10809"` (для socks нужен пакет `aiohttp-socks`).
* **Размер базы.** Оценки хранятся в SQLite в `data/bot.db`; она крошечная и
  хорошо переносит тысячу-другую записей на пользователя.
* **Бэкап.** Достаточно периодически копировать `data/bot.db`.
* **Обновление.** `git pull` (или пересборка Docker-образа) и перезапуск процесса —
  база с данными при этом сохраняется.
* **Свой ключ нейросети.** Ничего в конфиге прописывать не надо: каждый пользователь
  подключает свой ключ через `/key`.
